01What this system is

A local lakehouse built entirely with Docker Compose. Object storage, the table catalog, processing, query, orchestration and metadata management all run on a single Docker network (lakehouse), and services call each other by container name.

The demo use case is a medallion pipeline for daily Vietnamese stock prices (OHLCV). Each layer is a real Apache Iceberg table, registered in the Apache Polaris catalog, with data on MinIO. That is why Spark can write and Trino can read the same table.

Deliberately small: 5 symbols (FPT, VNM, ACB, HPG, MWG), and each run overwrites the whole table (createOrReplace) so the flow is easy to follow; switch to MERGE INTO for incremental.

05Medallion data flow

LayerCodeInput → outputMain logic
Ingestairflow/plugins/ingest_ohlcv.pyvnstock → s3://lakehouse/bronze/_landing/stock_ohlcv/ingest_date=YYYY-MM-DD/data.parquetPulls OHLCV per symbol (VCI source), adds symbol, source, ingested_at; writes parquet via boto3. Failing symbols are skipped; fails if no symbol has data.
Bronzespark/jobs/job_bronze.pylanding parquet → lakehouse.bronze.stock_ohlcvtime → trade_date; dedup by (symbol, trade_date), keeping the row with the latest ingested_at. Read schema declared explicitly.
Silverspark/jobs/job_silver.pybronze → lakehouse.silver.stock_ohlcvQuality rules: non-null keys, prices > 0, volume ≥ 0, candle constraints (high ≥ low, high ≥ max(open, close), low ≤ min(open, close)). Logs kept/dropped rows; fails if empty.
Goldspark/jobs/job_gold.pysilver → lakehouse.gold.stock_daily_metricsprev_close, daily_return, ma5, ma20, range_pct. Windows computed within each symbol by trade_date. Fails if empty.
QueryTrinogold tableSELECT … FROM lakehouse.gold.stock_daily_metrics

Common traits

  • Idempotent. Ingest overwrites the file per ingest_date, so re-running within a day leaves no junk. The Spark jobs use createOrReplace().
  • Iceberg tables use format v2, partitioned by symbol, located at s3://lakehouse/<namespace>/<table> (the catalog's default location).
  • Transform logic is factored into pure functions (transform_bronze, clean_silver, build_gold), so it can be tested with hand-built DataFrames, without MinIO or Polaris.

06Catalog: Apache Polaris

AspectConfiguration
Endpointhttp://polaris:8181/api/catalog, warehouse/prefix lakehouse
AuthOAuth2 client-credentials root / POLARIS_SECRET, scope PRINCIPAL_ROLE:ALL required
Metadata persistencePostgres via POLARIS_PERSISTENCE_TYPE=relational-jdbc (database polaris)
Catalog storageS3: endpoint = MinIO, pathStyleAccess=true, stsUnavailable=true, region=us-east-1, allowedLocations=s3://lakehouse/
Privilegescatalog_admin is additionally granted CATALOG_MANAGE_CONTENT (needed for DROP TABLE purge and metrics reporting)
Catalog propertiespolaris.config.drop-with-purge.enabled=true
Namespacesbronze, silver, gold, created via the Iceberg REST API
Health/q/health on port 8182, container-internal only

Because stsUnavailable=true, Polaris does not vend temporary credentials to clients. Each engine brings its own MinIO keys. Polaris itself reads/writes metadata files using the AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_REGION environment variables.

08Orchestration: Airflow

  • DAG lakehouse_ohlcv (airflow/dags/lakehouse_ohlcv_dag.py): ingest_landing → build_bronze → build_silver → build_gold. Schedule 0 18 * * 1-5 (18:00 Mon–Fri, Asia/Ho_Chi_Minh time), catchup=False, retries=1. New DAGs start paused by default.
  • Spark submission via the Spark Standalone REST API spark-master:6066 (airflow/plugins/spark_rest.py), deploy mode cluster: the driver runs on spark-worker, so Airflow needs neither Java nor spark-submit. The task waits for driver state FINISHED (30-minute timeout) and fails on FAILED, ERROR or KILLED.
  • Ingest runs inside the scheduler (PythonOperator), reading MINIO_* from env.
  • Connections are created in code by airflow/scripts/init.sh (delete, then recreate): spark_rest_conn, minio_conn, postgres_conn, trino_conn, datahub_conn.
  • The custom-airflow:2.9.2 image (from apache/airflow:2.9.2-python3.11) installs dbt-core/dbt-spark 1.8.0, the http/amazon/postgres/trino providers, acryl-datahub[airflow] 0.12.1.5, pandas 2.1.4, pyarrow 14.0.2, using the official Airflow 2.9.2 constraints.

09Metadata & lineage: DataHub

DataHub v0.12.1 (matches acryl-datahub[airflow]==0.12.1.5), ported from the MySQL quickstart onto this repo's infrastructure:

  • Postgres (database datahub), Kafka kafka:29092, Elasticsearch as the graph store (no Neo4j). schema-registry is added because DataHub requires one.
  • datahub-gms runs the MAE/MCE/PE consumers embedded. UI on port 9002.
  • Spark emits lineage via the acryl-spark-lineage JAR, Airflow via datahub_conn. Lineage has not yet been verified in the UI.

12Operations

Run inside WSL, from the repo root:

docker compose config --quiet          # check the 8 modules merge cleanly
docker compose build                   # build custom-spark, custom-airflow
docker compose up -d                   # start the whole stack
docker compose ps -a                   # status + health
docker compose logs -f <service>
docker compose down                    # stop (keeps volumes)

Quick checks

docker exec trino trino --execute "SHOW SCHEMAS FROM lakehouse"   # bronze gold information_schema silver
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8181/api/catalog/v1/config  # 401 = Polaris is up

Run a Spark job by hand

spark-submit is not on the container's PATH; use the full path:

docker compose exec spark-master /opt/spark/bin/spark-submit \
  --py-files /opt/spark/jobs/common.py /opt/spark/jobs/job_bronze.py   # same for silver, gold
