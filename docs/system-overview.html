01Hệ thống này là gì

Một lakehouse chạy local dựng hoàn toàn bằng Docker Compose. Lưu trữ object, catalog bảng, xử lý, truy vấn, điều phối và quản lý metadata đều chạy trên một mạng Docker duy nhất (lakehouse), các service gọi nhau bằng tên container.

Bài toán demo là một pipeline medallion cho giá cổ phiếu Việt Nam theo ngày (OHLCV). Mỗi tầng là một bảng Apache Iceberg thật, đăng ký trong catalog Apache Polaris, dữ liệu nằm trên MinIO. Vì vậy Spark ghi và Trino đọc được cùng một bảng.

Cố ý giữ nhỏ: 5 mã (FPT, VNM, ACB, HPG, MWG), mỗi lần chạy ghi đè toàn bộ bảng (createOrReplace) để luồng dễ theo dõi; muốn incremental thì đổi sang MERGE INTO.

04Chuỗi khởi động

Phần lớn depends_on dùng service_healthy hoặc service_completed_successfully, nên các service khởi động đúng thứ tự, không chạy đua nhau:

postgres ─▶ postgres-setup ─┬─▶ polaris-bootstrap ─▶ polaris ─┬─▶ polaris-setup (cần cả minio-setup)
                            │                                 └─▶ trino
                            └─▶ airflow-init ─▶ airflow-webserver, airflow-scheduler
minio ─▶ minio-setup
spark-master ─▶ spark-worker, spark-history;  spark-fix-permissions + spark-master ─▶ spark-thrift
zookeeper ─▶ kafka ─┬─▶ kafka-setup ─────────────────┐
                    └─▶ schema-registry ─────────────┤
elasticsearch ─▶ datahub-elasticsearch-setup ────────┼─▶ datahub-upgrade ─▶ datahub-gms ─┬─▶ datahub-frontend-react
postgres-setup ─▶ datahub-postgres-setup ────────────┘                                  └─▶ datahub-actions

Lần docker compose up -d thứ N vẫn thành công: mọi job setup đều idempotent (đã kiểm tra).

05Luồng dữ liệu medallion

TầngCodeĐầu vào → đầu raLogic chính
Ingestairflow/plugins/ingest_ohlcv.pyvnstock → s3://lakehouse/bronze/_landing/stock_ohlcv/ingest_date=YYYY-MM-DD/data.parquetKéo OHLCV từng mã (nguồn VCI), gắn symbol, source, ingested_at; ghi parquet qua boto3. Mã lỗi thì bỏ qua; không mã nào có dữ liệu thì fail.
Bronzespark/jobs/job_bronze.pylanding parquet → lakehouse.bronze.stock_ohlcvtime → trade_date; khử trùng lặp theo (symbol, trade_date), giữ bản có ingested_at mới nhất. Schema đọc khai báo tường minh.
Silverspark/jobs/job_silver.pybronze → lakehouse.silver.stock_ohlcvLuật chất lượng: khoá không null, giá > 0, volume ≥ 0, ràng buộc nến (high ≥ low, high ≥ max(open, close), low ≤ min(open, close)). Log số dòng giữ/loại; fail nếu rỗng.
Goldspark/jobs/job_gold.pysilver → lakehouse.gold.stock_daily_metricsprev_close, daily_return, ma5, ma20, range_pct. Window tính riêng trong từng mã theo trade_date. Fail nếu rỗng.
QueryTrinobảng goldSELECT … FROM lakehouse.gold.stock_daily_metrics

Đặc điểm chung

  • Idempotent. Ingest ghi đè file theo ingest_date, nên chạy lại trong ngày không sinh rác. Các job Spark dùng createOrReplace().
  • Bảng Iceberg dùng format v2, partition theo symbol, nằm tại s3://lakehouse/<namespace>/<bảng> (location mặc định của catalog).
  • Logic transform tách thành hàm thuần (transform_bronze, clean_silver, build_gold), nên test được bằng DataFrame dựng tay, không cần MinIO hay Polaris.

08Điều phối: Airflow

  • DAG lakehouse_ohlcv (airflow/dags/lakehouse_ohlcv_dag.py): ingest_landing → build_bronze → build_silver → build_gold. Lịch 0 18 * * 1-5 (18:00 thứ 2–6, giờ Asia/Ho_Chi_Minh), catchup=False, retries=1. DAG mới tạo mặc định ở trạng thái paused.
  • Submit Spark qua Spark Standalone REST API spark-master:6066 (airflow/plugins/spark_rest.py), deploy mode cluster: driver chạy trên spark-worker, nên Airflow không cần Java hay spark-submit. Task chờ trạng thái driver FINISHED (timeout 30 phút); gặp FAILED, ERROR hoặc KILLED thì fail.
  • Ingest chạy ngay trong scheduler (PythonOperator), đọc MINIO_* từ env.
  • Connections do airflow/scripts/init.sh tạo bằng code (xoá rồi tạo lại): spark_rest_conn, minio_conn, postgres_conn, trino_conn, datahub_conn.
  • Image custom-airflow:2.9.2 (từ apache/airflow:2.9.2-python3.11) cài dbt-core/dbt-spark 1.8.0, các provider http/amazon/postgres/trino, acryl-datahub[airflow] 0.12.1.5, pandas 2.1.4, pyarrow 14.0.2, dùng constraints chính thức của Airflow 2.9.2.

09Metadata & lineage: DataHub

DataHub v0.12.1 (khớp acryl-datahub[airflow]==0.12.1.5), chuyển từ bản quickstart MySQL sang dùng hạ tầng của repo:

  • Postgres (database datahub), Kafka kafka:29092, Elasticsearch làm graph store (không có Neo4j). schema-registry được thêm vào vì DataHub bắt buộc phải có.
  • datahub-gms chạy các consumer MAE/MCE/PE ngay bên trong. UI ở cổng 9002.
  • Spark gửi lineage qua JAR acryl-spark-lineage, Airflow gửi qua datahub_conn. Chưa kiểm chứng lineage thực tế trên UI.

12Vận hành

Chạy trong WSL, tại thư mục gốc repo:

docker compose config --quiet          # kiểm tra 7 module merge hợp lệ
docker compose build                   # build custom-spark, custom-airflow
docker compose up -d                   # bật toàn bộ stack
docker compose ps -a                   # trạng thái + health
docker compose logs -f <service>
docker compose down                    # dừng (giữ volume)

Kiểm tra nhanh

docker exec trino trino --execute "SHOW SCHEMAS FROM lakehouse"   # bronze gold information_schema silver
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8181/api/catalog/v1/config  # 401 = Polaris đang chạy

Chạy job Spark bằng tay

spark-submit không nằm trong PATH của container, phải dùng đường dẫn đầy đủ:

docker compose exec spark-master /opt/spark/bin/spark-submit \
  --py-files /opt/spark/jobs/common.py /opt/spark/jobs/job_bronze.py   # tương tự silver, gold

Test

venv/bin/python -m pytest -m "not spark"        # host (WSL), không cần Java
# test Spark: chạy trong spark-master (xem CLAUDE.md, mục Common commands)
